周报小助手

把草稿润色成领导爱看的周报

模拟模式：不会发出任何网络请求，也无需密钥；输出为预置的示例周报，仅用于演示与测试。去掉网址里的 ?mock 即恢复正常。
模型与密钥

可从下拉建议中选择，以服务商官方模型 ID 为准，可自行修改。

密钥仅保存在本机，请求只发往你填写的服务商。
  • 密钥只保存在本机浏览器（localStorage），不会上传给本工具作者；本工具没有服务器。
  • 点击「开始润色」时，密钥与草稿会直接发送到你填写的模型服务商，请确认 Base URL 正确，并遵守公司关于外部 AI 与数据外发的规定。
  • 不要在公司公用电脑上保存密钥；离开前请点「清除密钥」。
  • 这份 HTML 可以发给同事共用，但每个人必须填写自己的 API Key；不要把别人的密钥写进文件或聊天里转发。密钥存在当前这台电脑的这个浏览器里，换设备或换浏览器需要自己再填一次。
  • 这是个人本地工具。把密钥放在网页前端与部分官方安全建议（如 OpenAI 不建议在浏览器暴露密钥）相冲突，风险由你自行承担；本工具通过「密钥不出本机、只发往你指定的地址、可一键清除」降低风险，但无法消除 XSS 或恶意浏览器扩展读取 localStorage 的风险。
请求失败 / 跨域（CORS）说明

本工具在浏览器里直接连接服务商，能否成功取决于服务商是否允许浏览器跨域访问（双击打开时来源为 null）。

  • OpenAI 与 DeepSeek 通常允许浏览器直连，推荐优先用它们验证「双击即可用」。
  • Kimi、通义千问（百炼）、智谱及自定义网关不一定开放跨域，策略也可能变化。

如果出现「Failed to fetch」/ CORS 报错而密钥确认无误：

  1. 先改用 DeepSeek 或 OpenAI 验证流程；
  2. 或在本机自行运行一个你自己可控的反向代理（转发到目标 Base URL 并补上 CORS 头），再把 Base URL 改成该本地地址；
  3. 不要使用公共 CORS 代理，它会让第三方看到你的密钥和草稿。

注意：部分服务商对错误响应（如密钥错误 401）不带 CORS 头，浏览器也会显示为 Failed to fetch，所以请同时核对密钥。
